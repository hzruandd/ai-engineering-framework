## 一、设计目标

建立统一的前后端状态码规范，实现：

1. **业务告警**：明确告知用户操作失败原因，引导用户正确操作
2. **逻辑控制**：前端根据特定状态码执行相应逻辑（如跳转登录、权限控制）
3. **异常隔离**：系统级异常对用户友好提示，技术细节仅在控制台展示供开发排查

## 二、状态码分类设计

### 2.1 三大分类总览

| 分类 | 状态码 | 异常来源 | 用户提示 | 控制台 | 说明 |
|------|--------|----------|----------|--------|------|
| **第1类：业务告警** | 500 | BusinessException | ✅ 弹框显示msg | - | 业务校验失败，msg对用户友好 |
| **第2类：指定状态码** | 401/403/0-17/100-104等 | 特定异常 | 按需提示 | - | 前端根据code做逻辑处理 |
| **第3类：系统异常** | 600/601 | RuntimeException/RpcException | ✅ 友好提示 | ✅ 打印msg | 系统级错误，msg含技术细节 |

## 四、前端处理规范

### 4.1 响应拦截器处理逻辑

```javascript
// 响应拦截器处理建议
service.interceptors.response.use(
  (res) => {
    const code = res.data.code || 200;
    const msg = res.data.msg || '未知错误';

    // 成功
    if (code === 200) {
      return res.data;
    }

    // 第1类：业务告警 (code=500)
    // 直接弹框显示msg，msg是后端BusinessException给的用户友好提示
    if (code === 500) {
      Message.error(msg);
      return Promise.reject(new Error(msg));
    }

    // 第2类：指定状态码 - Token/登录相关 (code=401 或 code<0)
    if (code === 401 || code < 0) {
      // 弹框提示，跳转登录页
      MessageBox.confirm('登录状态已过期，请重新登录', '系统提示', {
        confirmButtonText: '重新登录',
        type: 'warning'
      }).then(() => {
        store.dispatch('FedLogOut').then(() => router.push('/login'));
      });
      return Promise.reject(new Error('未登录'));
    }

    // 第2类：指定状态码 - 权限相关 (code=403)
    if (code === 403) {
      Notification.error({ title: '权限不足', message: msg });
      return Promise.reject(new Error(msg));
    }

    // 第2类：指定状态码 - Sentinel限流/降级 (code=100-104, 429)
    if ([100, 101, 102, 103, 104, 429].includes(code)) {
      Message.warning(msg || '系统繁忙，请稍后再试');
      return Promise.reject(new Error(msg));
    }

    // 第3类：系统异常 (code=600, 601)
    // 给用户友好提示，详细信息打印到控制台供开发排查
    if (code === 600 || code === 601) {
      console.error('[系统异常]', res.config.url, msg);
      Message.error('系统异常，请稍后再试');
      return Promise.reject(new Error(msg));
    }

    // 其他未知状态码
    console.warn('[未知状态码]', code, msg);
    Notification.error({ title: msg });
    return Promise.reject(new Error(msg));
  },
  (error) => {
    // HTTP层面的错误（网络错误、超时等）
    // ...
  }
);
```

|------|--------|--------|------|----------|

## 五、Dubbo RPC异常传递规范

### 5.1 问题背景

在微服务架构中，BFF层通过Dubbo RPC调用下游服务。当下游服务抛出某些异常时，如果BFF层类路径中没有对应的异常类，会导致反序列化失败，产生NPE。

**典型问题**：
- 下游服务抛出 `DuplicateKeyException`（来自spring-tx包）
- BFF层排除了 `spring-boot-starter-jdbc`，没有此类
- Dubbo反序列化失败，BFF收到NPE而非原始异常

### 5.2 CustomExceptionFilter 异常转换

`CustomExceptionFilter` 在Provider端处理异常，将Consumer端可能不存在的异常类转换为 `RpcException`（code=601）：

| 原始异常 | 转换后 | 说明 |
|----------|--------|------|
| `DuplicateKeyException` | `BusinessException(500, msg)` | 唯一键冲突，业务异常 |
| `BindException` | `RpcException(601, msg)` | 参数绑定异常，RPC异常 |

**处理逻辑**：
```java
// DuplicateKeyException: 转换为BusinessException，前端按业务告警处理
if (className.startsWith("org.springframework.dao.DuplicateKeyException")) {
    String msg = exception.getMessage();
    // 提取 "Duplicate entry 'xxx' for key 'yyy'" 中的关键信息
    if (msg != null && msg.contains("Duplicate entry")) {
        // 截取关键部分
        msg = msg.substring(start, end).trim();
    } else {
        msg = "数据已存在，请勿重复操作";
    }
    appResponse.setException(new BusinessException(msg));
    return;
}

// BindException: 转换为RpcException，前端Notification显示
if (className.startsWith("org.springframework.validation.BindException")) {
    appResponse.setException(new RpcException(601, exception.getMessage(), exception));
    return;
}
```

### 5.3 前端处理

前端对600和601分开处理：

| 状态码 | UI组件 | 显示内容 | 说明 |
|--------|--------|----------|------|
| 600 | `Message.error` | "系统异常，请稍后再试" | 友好提示，msg打印到控制台 |
| 601 | `Notification.error` | msg原文 | 右上角抽屉式弹出，显示详细信息 |

```javascript
// code=600: 系统异常，友好提示
if (code === 600) {
    console.error('[系统异常]', res.config.url, 'msg:', res.data.msg);
    Message.error('系统异常，请稍后再试');
    return Promise.reject(new Error(msg));
}

// code=601: RPC调用异常，右上角Notification显示msg原文
if (code === 601) {
    console.error('[RPC异常]', res.config.url, 'msg:', res.data.msg);
    Notification.error({ title: '服务调用异常', message: msg });
    return Promise.reject(new Error(msg));
}
```

## 六、业务状态码扩展规范

### 6.1 BaseEnum 接口设计

框架提供了 `BaseEnum` 接口用于定义业务状态码，支持各业务模块定义自己的状态码枚举：

```java
/**
 * 系统返回码统一接口
 * code：状态码
 * message：用户友好提示信息
 */
public interface BaseEnum {
    Integer getCode();
    String getMessage();

    default Boolean success() {
        return BaseCode.OK.getCode().equals(this.getCode());
    }
}
```

### 6.2 BaseCode 通用状态码

`BaseCode` 是框架提供的通用状态码实现，位于 `city-parking-common-core`：

```java
public enum BaseCode implements BaseEnum {
    OK(200, "操作成功"),
    NOT_LOGIN(401, "未登录"),
    NOT_PERMISSION(403, "无权限"),
    FAIL(500, "操作失败"),        // 业务异常默认状态码
    SYSTEM_ERROR(600, "系统正在处理中..."),  // 系统级异常
    // ... 更多通用状态码
}
```

### 6.3 自定义业务状态码

各业务模块可以创建自己的状态码枚举，实现 `BaseEnum` 接口：

**位置规范**：`{service}-api/src/main/java/cn/city/parking/{module}/api/code/{Module}ApiCode.java`

**示例**：EOP模块业务状态码

```java
package cn.city.parking.eop.api.code;

import cn.city.parking.common.core.enums.BaseEnum;

/**
 * EOP模块业务状态码
 * 状态码范围建议：10000-19999
 */
public enum EopApiCode implements BaseEnum {

    // 查询相关 10000-10099
    QUERY_ERROR(10000, "查询异常"),
    QUERY_TIMEOUT(10001, "查询超时"),

    // 订单相关 10100-10199
    ORDER_NOT_FOUND(10100, "订单不存在"),
    ORDER_ALREADY_PAID(10101, "订单已支付，请勿重复操作"),
    ORDER_EXPIRED(10102, "订单已过期"),

    // 车辆相关 10200-10299
    VEHICLE_NOT_FOUND(10200, "车辆信息不存在"),
    VEHICLE_BINDLIMIT(10201, "车辆绑定数量已达上限"),
    ;

    private Integer code;
    private String message;

    EopApiCode(Integer code, String message) {
        this.code = code;
        this.message = message;
    }

    @Override
    public Integer getCode() {
        return code;
    }

    @Override
    public String getMessage() {
        return message;
    }
}
```

### 6.4 BusinessException 使用方式

`BusinessException` 支持多种构造方式，推荐使用 `BaseEnum` 方式：

```java
// ✅ 推荐方式1：使用BaseEnum枚举（最规范）
throw new BusinessException(EopApiCode.ORDER_NOT_FOUND);

// ✅ 推荐方式2：使用BaseEnum枚举 + 自定义消息
throw new BusinessException(EopApiCode.ORDER_NOT_FOUND, "订单号:" + orderId + "不存在");

// ✅ 推荐方式3：使用BaseEnum枚举 + 异常链
throw new BusinessException(EopApiCode.QUERY_ERROR, e);

// ✅ 方式4：简单消息（使用默认code=500）
throw new BusinessException("用户名已存在");

// ✅ 方式5：格式化消息
throw new BusinessException("用户%s的订单%s不存在", userId, orderId);

// ✅ 方式6：自定义code + 消息
throw new BusinessException(10100, "订单不存在");

// ✅ 静态方法调用（推荐，更简洁）
throw BusinessException.throwException(EopApiCode.ORDER_NOT_FOUND);
throw BusinessException.throwException("用户名已存在");
throw BusinessException.throwException(10100, "订单不存在");
```

### 6.5 状态码分配规范

为避免不同模块状态码冲突，建议按模块分配状态码范围：

| 模块 | 状态码范围 | 枚举类 |
|------|-----------|--------|
| 通用（BaseCode） | 0-999 | `BaseCode` |
| EOP运营平台 | 10000-19999 | `EopApiCode` |
| RBAC权限 | 20000-29999 | `RbacApiCode` |
| 订单服务 | 30000-39999 | `OrderApiCode` |
| 支付服务 | 40000-49999 | `PaymentApiCode` |
| 设备服务 | 50000-59999 | `DeviceApiCode` |
| 微信服务 | 60000-69999 | `WxMpApiCode` |

### 6.6 前端处理建议

对于自定义业务状态码，前端处理建议：

```javascript
// 响应拦截器
if (code >= 10000 && code < 100000) {
    // 自定义业务状态码，按业务告警处理
    // msg是后端枚举或自定义的用户友好提示
    Message.error(msg);
    return Promise.reject(new Error(msg));
}
```

## 七、特殊场景处理

### 7.1 静默模式 (silent)

某些接口失败时不需要全局错误提示（如logout），可配置静默模式：

```javascript
// API定义
export function logout() {
  return request({
    url: '/auth/eop/logout',
    method: 'delete',
    silent: true  // 静默模式：失败时不显示全局错误提示
  })
}

// 响应拦截器中处理
(error) => {
  if (error.config?.silent) {
    return Promise.reject(error);  // 静默模式，不显示错误提示
  }
  // ... 正常错误处理
}
```

### 7.2 不需要Token的接口

登录、验证码等接口不需要Token，配置 `isToken: false`：

```javascript
export function login(username, password, code, uuid) {
  return request({
    url: '/auth/eop/login',
    headers: { isToken: false },  // 不需要token
    method: 'post',
    data: { username, password, code, uuid },
    notIntercept: true  // token失效时也不拦截此接口
  })
}
```

### 7.3 前端Token过期检查

前端在请求拦截器中也会检查Token有效性：

```javascript
// auth.js
export function getToken() {
  if (isTokenExpired()) {
    removeToken();
    return null;
  }
  return localStorage.getItem(TOKEN_KEY);
}

// request.js 请求拦截器
if (!isToken) {
  const token = getToken();
  if (!token) {
    // 前端检测到Token过期，直接拦截
    Message.error('登录已过期，请重新登录');
    router.push('/login');
    return Promise.reject(new Error('Token已过期'));
  }
}
```

## 七、状态码使用示例

### 7.1 后端抛出业务异常

```java
// 业务校验失败，抛出BusinessException
// 前端收到 code=500, msg="用户名已存在"，弹框提示
if (userService.existsByUsername(username)) {
    throw new BusinessException("用户名已存在");
}

// 带自定义状态码的业务异常
// 前端收到 code=14, msg="用户名密码错误达3次..."
throw new BusinessException(BaseCode.LOGIN_LIMIT.getCode(), BaseCode.LOGIN_LIMIT.getMessage());
```

### 7.2 后端系统异常

```java
// RuntimeException会被全局异常处理器捕获
// 前端收到 code=600, msg=异常信息
// 前端显示"系统异常，请稍后再试"，控制台打印详细msg
throw new RuntimeException("数据库连接失败: Connection refused");
```

### 7.3 前端处理示例

```javascript
// 调用API
userApi.createUser(userData).then(res => {
  // code=200，成功
  Message.success('创建成功');
}).catch(error => {
  // 错误已被响应拦截器处理，这里可以做额外逻辑
  console.log('创建失败', error.message);
});
```
