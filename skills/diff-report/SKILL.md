# 代码修改报告生成器

> **使用场景**：提交代码前、Code Review 前、版本发布前
> **目标**：快速了解本次改动的范围、影响和风险

## 使用方式

```bash
# 生成当前分支相对于 master 的修改报告
/diff-report

# 指定对比的基准分支
/diff-report develop

# 指定输出文件名
/diff-report master CHANGE_REPORT_20260123.md
```

## 执行流程

### 第一步：获取分支差异信息

1. **获取当前分支名称**：
   ```bash
   git branch --show-current
   ```

2. **对比当前分支与 master 分支的差异**：
   ```bash
   # 统计信息
   git diff master...HEAD --stat

   # 文件状态
   git diff master...HEAD --name-status
   ```

3. **获取提交历史**：
   ```bash
   git log master..HEAD --oneline --graph
   ```

### 第二步：分析代码变更

阅读实际的代码变更内容：
```bash
git diff master...HEAD
```

对以下内容进行分析：
- 新增的文件和类
- 修改的文件和方法
- 删除的文件和代码
- 数据库 schema 变更（SQL 文件、Entity 字段）
- 配置文件变更（bootstrap.yml、application.yml）
- POM 依赖变更

### 第三步：生成修改报告

生成以下格式的报告，保存到项目根目录：

**报告路径**：`CHANGE_REPORT_{timestamp}.md`

**报告模板**：

```markdown

**报告生成时间**：{当前时间}
**当前分支**：{分支名}
**对比基准**：master
**提交数量**：{提交数}

## 分析要点

### 1. 代码变更分析

- **新增功能**：识别新增的类、方法、接口
- **功能修改**：识别修改的方法、逻辑变更
- **代码删除**：识别删除的类、方法、废弃的功能
- **重构**：识别代码结构调整、优化

### 2. 数据库变更分析

- **表结构变更**：新增表、修改表、删除表
- **字段变更**：新增字段、修改字段、删除字段
- **索引变更**：新增索引、删除索引
- **数据迁移**：是否需要数据迁移

### 3. 配置变更分析

- **应用配置**：bootstrap.yml、application.yml
- **Nacos 配置**：远程配置变更
- **环境变量**：新增或修改的环境变量
- **端口变更**：服务端口变更

### 4. 依赖变更分析

- **新增依赖**：新引入的第三方库
- **删除依赖**：移除的依赖
- **版本升级**：依赖版本变更
- **冲突风险**：依赖冲突检查

### 5. 影响范围分析

- **模块影响**：影响哪些模块
- **接口影响**：是否影响对外接口
- **数据影响**：是否影响数据结构
- **性能影响**：是否影响性能

### 6. 风险评估

- **技术风险**：技术实现的风险
- **业务风险**：业务逻辑的风险
- **兼容性风险**：向下兼容性
- **性能风险**：性能下降风险

## 常用 Git 命令

```bash
# 查看当前分支
git branch --show-current

# 查看文件变更统计
git diff master...HEAD --stat

# 查看文件变更状态
git diff master...HEAD --name-status

# 查看提交历史
git log master..HEAD --oneline

# 查看详细变更内容
git diff master...HEAD

# 查看某个文件的变更
git diff master...HEAD -- path/to/file

# 查看新增的文件
git diff master...HEAD --diff-filter=A --name-only

# 查看修改的文件
git diff master...HEAD --diff-filter=M --name-only

# 查看删除的文件
git diff master...HEAD --diff-filter=D --name-only
```

## 注意事项

1. **报告准确性**：确保分析准确，不遗漏重要变更
2. **风险识别**：重点识别高风险变更
3. **测试建议**：提供具体的测试建议
4. **部署说明**：提供清晰的部署步骤
5. **回滚方案**：提供可行的回滚方案
