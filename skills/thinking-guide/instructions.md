## 🎯 工具概述

### 什么是 Sequential Thinking？

Sequential Thinking 是一个结构化思考工具，帮助 AI 通过逐步推理的方式解决复杂问题。它的核心特点：

- ✅ **透明化思考过程**：让用户看到完整的分析推理
- ✅ **动态调整思路**：允许在思考过程中修正方向
- ✅ **假设验证机制**：生成假设后必须验证
- ✅ **迭代优化**：不满意时可以重新思考

### 核心价值

| 价值点 | 说明 |
|--------|------|
| **提高准确性** | 通过逐步推理减少错误判断 |
| **增强可信度** | 用户可以看到完整的分析过程 |
| **避免遗漏** | 系统化分析确保考虑所有因素 |
| **支持复杂决策** | 权衡多种方案的优劣 |

## 🛠️ 使用方法

### 基本使用流程

```
1. 识别场景 → 2. 启动思考 → 3. 逐步推理 → 4. 验证结论 → 5. 输出答案
```

### 思考步骤模板

```markdown
**思考 1/N：理解问题**
- 用户的核心诉求是什么？
- 涉及哪些模块/系统？
- 有哪些约束条件？
- 预期目标是什么？

**思考 2/N：收集信息**
- 现有实现是怎样的？
- 相关的配置和数据？
- 是否有类似案例？
- 缺少哪些信息？

**思考 3/N：分析根因/设计方案**
- 问题的根本原因？（排查场景）
- 可行的解决方案？（设计场景）
- 各方案的优劣？
- 潜在的风险点？

**思考 4/N：制定计划**
- 具体实施步骤？
- 先做什么后做什么？
- 需要哪些资源？
- 如何验证效果？

**思考 5/N：验证结论**
- 方案是否可行？
- 是否有遗漏？
- 风险是否可控？
- 最终建议？
```

### 动态调整思路

思考过程中可以：

- **增加步骤**：发现需要更深入分析时
- **修正方向**：发现之前的假设错误时
- **分支探索**：需要对比多个方案时
- **回溯重来**：发现思路有问题时

## 💡 思考原则

### 核心原则

#### 1. 逐步推进原则

- ✅ **一步一步分析**：不要跳跃式思考
- ✅ **每步有结论**：每个思考步骤都要有明确产出
- ✅ **循序渐进**：从简单到复杂，从整体到细节
- ❌ **不要跳步**：不要省略中间推理过程

#### 2. 质疑假设原则

- ✅ **验证假设**：每个假设都要验证
- ✅ **寻找反例**：主动寻找可能推翻结论的证据
- ✅ **多角度思考**：从不同视角看问题
- ❌ **不要想当然**：不要基于未验证的假设得出结论

#### 3. 探索备选原则

- ✅ **考虑多个方案**：至少考虑 2-3 个备选方案
- ✅ **权衡利弊**：分析每个方案的优缺点
- ✅ **对比筛选**：基于明确标准选择最优方案
- ❌ **不要只看一种可能**：避免思维定势

#### 4. 动态调整原则

- ✅ **允许修正**：发现错误时及时调整
- ✅ **灵活应变**：根据实际情况调整步骤
- ✅ **持续优化**：不断完善思考过程
- ❌ **不要固执己见**：发现问题要勇于推翻

#### 5. 过滤无关原则

- ✅ **聚焦核心**：忽略与当前步骤无关的信息
- ✅ **抓住重点**：优先分析关键因素
- ✅ **避免发散**：不要陷入无关细节
- ❌ **不要被干扰**：不被次要信息带偏

## 📚 实践示例

### 示例 1：性能优化场景

**用户问题**："这个接口响应时间太慢了，帮我优化一下"

#### ❌ 错误做法（直接回答）

```
建议：
1. 添加缓存
2. 优化 SQL 查询
3. 使用异步处理
```

**问题**：没有分析根因，没有验证假设，方案可能不适用。

#### ✅ 正确做法（使用 sequential-thinking）

```
**思考 1/6：理解问题**
- 哪个接口慢？慢到什么程度？
- 正常响应时间是多少？现在是多少？
- 什么时候开始变慢的？
- 是所有请求都慢还是特定场景？

**思考 2/6：收集信息**
- 查看接口代码实现
- 检查慢查询日志
- 分析调用链路和耗时分布
- 查看服务器资源使用情况

**思考 3/6：定位瓶颈**
- 数据库查询耗时 800ms（主要瓶颈）
- 外部 API 调用耗时 200ms
- 业务逻辑处理耗时 50ms
→ 结论：数据库查询是主要瓶颈

**思考 4/6：分析根因**
- 查看执行计划：发现全表扫描
- 检查索引：user_id 字段缺少索引
- 数据量：表有 500 万条记录
→ 根因：缺少索引导致全表扫描

**思考 5/6：设计方案**
- 方案 A：添加 user_id 索引（立即见效，低风险）
- 方案 B：引入 Redis 缓存（长期优化，需改造）
- 方案 C：分库分表（成本高，周期长）
→ 推荐：先执行方案 A，再考虑方案 B

**思考 6/6：验证结论**
- 添加索引后预期响应时间：< 100ms
- 风险：索引维护成本增加（可接受）
- 监控指标：接口响应时间、数据库 CPU
→ 最终方案可行
```

### 示例 2：架构设计场景

**用户问题**："如何设计一个高可用的用户认证系统？"

```
**思考 1/7：理解需求**
- 用户规模：预计百万级
- 可用性要求：99.99%
- 安全性要求：高
- 性能要求：登录响应 < 200ms

**思考 2/7：分析现有方案**
- Session 方案：服务端存储，难以扩展
- JWT 方案：无状态，适合分布式
- OAuth 2.0：标准协议，功能完善

**思考 3/7：技术选型**
- 基础方案：JWT + Redis
- 原因：无状态 + 高性能 + 支持水平扩展
- 备选：Session + Redis（兼容性更好）

**思考 4/7：架构设计**
- 认证服务：独立微服务
- Token 存储：Redis 集群（主从 + 哨兵）
- Token 刷新：双 Token 机制（Access + Refresh）
- 安全加固：HTTPS + 加密存储 + 限流

**思考 5/7：高可用设计**
- 服务层：多副本部署 + 负载均衡
- 存储层：Redis 主从 + 哨兵自动切换
- 降级策略：本地缓存兜底
- 监控告警：健康检查 + 实时告警

**思考 6/7：风险评估**
- 风险 1：Redis 故障 → 降级到本地缓存
- 风险 2：Token 泄露 → 定期轮换 + 黑名单机制
- 风险 3：性能瓶颈 → 水平扩展 + 缓存优化

**思考 7/7：实施计划**
1. 第一阶段：基础认证服务 + JWT
2. 第二阶段：Redis 集群 + 高可用
3. 第三阶段：监控告警 + 安全加固
→ 分阶段实施，降低风险
```

### 示例 3：Bug 排查场景

**用户问题**："为什么用户登录后，有时候会自动退出？"

```
**思考 1/6：理解问题**
- 频率：偶发（约 5% 用户）
- 触发条件：不确定
- 环境：生产环境
- 影响：用户体验差，投诉增多

**思考 2/6：收集线索**
- 查看日志：发现 Token 验证失败
- 用户反馈：多发生在切换页面时
- 时间规律：无明显规律
- 浏览器：Chrome、Safari 都有

**思考 3/6：提出假设**
- 假设 1：Token 过期时间设置不合理
- 假设 2：前端 Token 存储问题
- 假设 3：后端 Token 校验逻辑有 Bug
- 假设 4：网络问题导致 Token 丢失

**思考 4/6：逐一验证**
- 假设 1：检查配置，过期时间 7 天（正常）❌
- 假设 2：检查代码，发现用 sessionStorage 存储 ✅
- 假设 3：检查逻辑，未发现异常 ❌
- 假设 4：网络日志正常 ❌
→ 根因：sessionStorage 在新标签页不共享

**思考 5/6：设计解决方案**
- 方案 A：改用 localStorage（简单，风险低）
- 方案 B：改用 Cookie（兼容性好，但安全性需加固）
- 方案 C：不改，用户体验差 ❌
→ 推荐方案 A

**思考 6/6：验证方案**
- localStorage 支持跨标签页
- 安全性：设置合理过期时间 + HTTPS
- 兼容性：现代浏览器都支持
→ 方案可行，可以实施
```

## ✨ 最佳实践

### 1. 思考前的准备

- ✅ **明确问题**：确保理解用户的真实诉求
- ✅ **收集信息**：先收集必要的信息再开始思考
- ✅ **设定目标**：明确思考要达到的目标

### 2. 思考中的技巧

- ✅ **分层思考**：从宏观到微观，从整体到局部
- ✅ **对比验证**：通过对比多个方案来验证结论
- ✅ **追问细节**：不断追问"为什么"，深入本质
- ✅ **记录思路**：记录思考过程，方便回溯

### 3. 思考后的总结

- ✅ **结论明确**：给出清晰的结论和建议
- ✅ **风险提示**：说明潜在风险和注意事项
- ✅ **可执行性**：确保方案具有可操作性

### 4. 与用户的互动

- ✅ **透明化**：让用户看到完整的思考过程
- ✅ **可理解**：使用用户能理解的语言
- ✅ **可追溯**：用户可以看到每一步的推理

## ⚠️ 常见错误

### 错误 1：直接给答案

❌ **错误**：看到问题直接给出答案
✅ **正确**：先思考分析，再给出答案

### 错误 2：跳过验证

❌ **错误**：基于假设得出结论，不验证
✅ **正确**：每个假设都要验证

### 错误 3：单一方案

❌ **错误**：只考虑一种方案
✅ **正确**：至少考虑 2-3 个备选方案

### 错误 4：忽略风险

❌ **错误**：只说优点，不提风险
✅ **正确**：明确指出风险和应对措施

### 错误 5：思考过于简单

❌ **错误**：复杂问题用 2-3 步思考完成
✅ **正确**：根据问题复杂度调整思考步骤（通常 5-8 步）

### 错误 6：思考流于形式

❌ **错误**：每步都写"分析中..."但没有实质内容
✅ **正确**：每步都要有明确的分析和结论

### 错误 7：不敢修正

❌ **错误**：发现思路错误也不修正，硬着头皮走下去
✅ **正确**：发现问题及时调整思路
