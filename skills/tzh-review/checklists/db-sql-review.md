# 数据库与 SQL 专项评审清单

## 适用门槛

只要涉及以下任一内容，必须执行本清单：
- SQL
- 字段
- 索引
- DDL
- DML
- 数据修复脚本
- Doris
- Dinky
- MV
- 报表口径
- 订单、支付、计费、月租、券包、发票、清分、对账、开闸等核心数据读写

## 一、SQL 查询质量

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 是否走索引 | 全表扫描、回表过多、Using filesort、Using temporary | 核心 SQL 无法说明索引命中，至少 `P1` |
| 条件是否精确 | 条件缺失、模糊条件过宽、租户/停车场/商户条件缺失 | 核心隔离条件缺失可升 `P0` |
| 排序分页是否合理 | 深分页、非索引排序、`limit` 过大 | 核心链路性能风险至少 `P1` |
| 聚合是否可控 | 大聚合、无预计算、无分层汇总 | 影响结算/报表链路至少 `P1` |
| 是否提供 EXPLAIN | 核心 SQL 未给 EXPLAIN | `P1` |
| 是否存在 `select *` | 无字段收敛、宽表查询 | 视数据量与场景 `P2/P1` |

## 二、UPDATE / DELETE 风险

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| WHERE 是否精确 | 缺少主键、唯一键、租户隔离条件 | 核心表高危写操作直接 `P0` |
| 是否可能误更新多行 | 条件过宽、联表条件不稳 | 影响核心数据一致性可 `P0` |
| 是否有 dry-run / 验证 SQL | 上线前后无法核对影响范围 | 至少 `P1` |
| 是否支持幂等重跑 | 重跑会重复改数 | 数据修复脚本至少 `P1` |
| 是否限制批次 | 一次性扫全表、锁表时间不可控 | 大表写入风险至少 `P1` |

## 三、字段变更

### 1. 新增字段

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 是否可空 | 老数据是否可兼容 | 不清楚至少 `P1` |
| 默认值是否合理 | 默认值是否改变业务语义 | 核心状态/金额字段风险至少 `P1` |
| 新旧代码是否兼容 | 旧服务读写是否受影响 | 不清楚至少 `P1` |
| 是否需要回填 | 老数据缺失是否影响逻辑 | 核心逻辑失真可 `P0/P1` |

### 2. 删除字段

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 是否还有旧代码依赖 | 读写、报表、同步任务是否仍使用 | 兼容性不明确至少 `P1` |
| 是否存在灰度阶段 | 是否先停写再删字段 | 无过渡方案至少 `P1` |

### 3. 改名 / 类型 / 长度 / 精度变更

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 类型是否兼容 | `varchar -> bigint`、`int -> tinyint` 等 | 核心金额/状态/主键风险至少 `P1` |
| 长度是否够用 | 截断风险、编码风险 | 核心标识截断可 `P1` |
| 精度是否足够 | 金额、费率、税率、结算精度 | 可能错账直接 `P0` |
| 迁移策略是否明确 | 双写、回填、灰度 | 不明确至少 `P1` |

## 四、金额字段

必须核查：
- 单位是否一致：分、元、厘
- 精度是否足够
- 是否有四舍五入策略
- 是否存在金额累加/拆分逻辑变更
- 是否影响发票、清分、对账口径

风险判定：
- 金额字段精度或单位变更未验证：`P0`
- 金额汇总 SQL 口径变更未验证：`P0`

## 五、状态字段

必须核查：
- 状态枚举是否扩展
- 旧值是否兼容
- 状态流转是否闭环
- 异常状态、逆向状态是否可回滚

风险判定：
- 订单、支付、开票、开闸状态机异常：`P0/P1`

## 六、时间字段

必须核查：
- 时区
- 精度
- 默认值
- 排序字段是否影响索引
- 是否影响定时任务、报表窗口、对账账期

风险判定：
- 时间口径变更导致报表/对账失真：至少 `P1`，严重时 `P0`

## 七、租户 / 停车场 / 商户隔离字段

必须核查：
- 查询是否带租户条件
- 更新是否带租户条件
- 补数脚本是否限制停车场/商户范围
- 联表是否保留隔离条件

风险判定：
- 缺少核心隔离条件：直接 `P0`

## 八、索引评审

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 是否新增索引 | 是否真支持核心 SQL | 依据不足至少 `P1` |
| 是否删除索引 | 是否影响现网读路径 | 核心查询风险至少 `P1` |
| 联合索引顺序 | 最左前缀是否匹配 where/order by | 不匹配至少 `P1/P2` |
| 是否重复索引 | 名义不同、字段相同或前缀覆盖 | 可维护性 `P2` |
| 低选择性索引 | 状态、布尔字段单列索引 | 写放大与收益失衡 `P2/P1` |
| 写入影响 | 高频写表新增过多索引 | 性能风险 `P1/P2` |

## 九、大表 DDL

必须核查：
- 是否评估表规模
- 是否评估锁表时长
- 是否有在线变更方案
- 是否有前滚脚本
- 是否有回滚脚本
- 是否有验证 SQL
- 是否有执行窗口与责任人

风险判定：
- 大表 DDL 无评估、无回滚、无验证 SQL：直接 `P0`

## 十、DML 数据修复脚本

必须核查：
- 是否可重复执行
- 是否支持按批次执行
- 是否有影响范围预估
- 是否有执行前后校验 SQL
- 是否有回滚方案
- 是否写明责任人与执行窗口

风险判定：
- 不可重复执行：`P1`
- 无回滚、无验证 SQL：`P1`
- 核心表高危改数且条件不精确：`P0`

## 十一、EXPLAIN 结果

核心 SQL 至少检查：
- `type`
- `key`
- `rows`
- `filtered`
- `Extra`
- 是否命中预期联合索引
- 是否存在回表、临时表、文件排序

风险判定：
- 核心 SQL 未提供 EXPLAIN：`P1`
- EXPLAIN 明确显示高扫描且无缓解：`P1`，严重时 `P0`

## 十二、Doris / Dinky / MV / 报表同步影响

必须核查：
- 明细表字段变化是否影响 Doris / Dinky 任务
- 聚合口径是否变化
- MV 是否需要重建
- 报表字段、口径、时间窗是否变化
- 补数或回刷策略是否明确

风险判定：
- 口径变更未验证：`P1`
- 清分、对账、发票核心口径变更无验证：`P0`

## 十三、上线与回滚

必须提供：
- 前滚脚本
- 回滚脚本
- 验证 SQL
- 执行窗口
- 负责人

风险判定：
- 只有代码回滚，没有数据回滚或兼容策略：`P1`
- 大表 DDL 无回滚：`P0`

## 十五、数据库设计评审（新增）

> 规范依据：`database-engineering-standard.md` 第 1、2、3 章。

### 1. 表设计

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 是否符合业务模型 | 表与实体/关系是否对应 | 明显偏离至少 `P1` |
| 是否存在字段冗余 | 重复/派生字段无必要 | 可维护性 `P2` |
| 大字段是否污染主表 | `text`/`blob`/超长 `varchar` 未与热表分离 | 影响热表性能 `P1/P2` |
| 是否需要拆分扩展表 | 宽表、低频大字段 | 视场景 `P2/P1` |
| 是否评估数据增长 | 未评估行数量级与增速 | 大表无评估至少 `P1` |

### 2. 字段设计

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 类型是否合理 | 状态非 `tinyint`、金额非 `decimal`、时间非 `datetime` | 金额类型错误可 `P0`，其余 `P1/P2` |
| `varchar` 长度是否合理 | 无业务依据的 `varchar(255)`/`varchar(512)` | 至少 `P2` |
| 时间字段是否 `datetime` | 用 `varchar`/`int` 存时间 | `P1/P2` |
| 金额是否 `decimal` | 使用 `float`/`double` | 精度风险 `P0/P1` |
| 状态是否 `tinyint` | 用 `varchar` 存状态/枚举 | `P2` |

### 3. 主键设计

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 新表是否合理使用 `bigint` | 新表主键类型 | 不合理 `P2` |
| 存量 `varchar(64)` 是否保持兼容 | 是否被擅自迁移 | 擅改存量结构 `P0/P1` |
| 是否存在 UUID/随机字符串作主键 | 随机串聚簇主键（页分裂、索引膨胀） | 新表高频写 `P1`，其余 `P2` |

## 十六、索引设计评审（重点，新增）

> 规范依据：`database-engineering-standard.md` 第 4 章。第八章已覆盖"索引冗余/低选择性/写入影响"，本章聚焦"查询驱动与列顺序"，不重复。

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 查询驱动 | 索引是否依据 `WHERE`/`JOIN`/`ORDER BY`/`GROUP BY` 设计 | 无查询依据的索引 `P2`；核心查询无支撑索引 `P1` |
| 联合索引字段顺序 | 是否"等值→范围→排序→覆盖"，最左前缀是否匹配 | 顺序错误致 filesort/失效 `P1/P2` |
| 覆盖索引机会 | 高频查询是否可覆盖免回表 | 优化建议 `P2` |

## 十七、SQL 性能评审（增强）

> 规范依据：`database-engineering-standard.md` 第 5、6 章。第一章已覆盖 `SELECT *`/全表扫描，本章补充索引失效、模糊、深分页、写风险的专项判定。

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 查询问题 | `SELECT *`、全表扫描、大范围扫描 | 核心链路 `P1`，其余 `P2` |
| 索引失效（函数包字段） | `DATE_FORMAT`/`YEAR`/`MONTH`/`LEFT`/`HOUR` 包裹索引列 | 核心 SQL 全表扫描 `P1`，严重 `P0` |
| 模糊查询 | `LIKE '%xxx%'`；分析应改等值/前缀/搜索系统 | 大表片段模糊至少 `P1` |
| 分页问题 | `LIMIT offset`，特别是 `LIMIT 100000` 深分页 | 核心链路 `P1` |
| 写操作风险 | `UPDATE`/`DELETE` 缺 `WHERE`、影响大范围、大事务 | 缺精确 `WHERE` 直接 `P0` |

## 十八、PolarDB / MySQL 适配评审（新增）

> 规范依据：`database-engineering-standard.md` 第 8 章。

| 检查项 | 重点问题 | 风险判定 |
|---|---|---|
| 索引结构理解 | 是否理解主键=聚簇索引、二级索引回表 | 设计误解致性能问题 `P1/P2` |
| 大表风险 | 数据量、索引数量、DDL 影响是否评估 | 大表无评估 `P1`，无回滚/验证 `P0` |
| 在线变更 | 新增字段/索引是否评估在线 DDL 风险 | 大表未评估在线 DDL `P0/P1` |
| 读写分离 | 是否存在读写节点使用错误（写走只读/一致性读走从库） | 一致性/写失败风险 `P1` |

## 十九、Review 输出分类（增强）

在第十四章输出表格基础上，专项结论按以下四类归集，每个问题必须包含【问题 / 影响 / 等级 / 建议】：

- **数据库设计风险**（表/字段/主键，见第十五章）
- **索引风险**（见第八、十六章）
- **SQL 性能风险**（见第一、十七章）
- **PolarDB 风险**（见第十八章）

等级定义：

- `P0`：阻断上线
- `P1`：上线风险
- `P2`：优化建议

分类输出模板：

| 分类 | 问题 | 影响 | 等级 | 建议 | 证据 |
|---|---|---|---|---|---|
| 数据库设计风险 / 索引风险 / SQL性能风险 / PolarDB风险 |  |  | P0 / P1 / P2 |  |  |

## 二十、真实案例检查项（Review 依据）

> 与 `database-engineering-standard.md` 第 9 章一致，作为高频复现问题的强制核查点。

| 案例表 | 必查反模式 | 判定 | 规范做法 |
|---|---|---|---|
| `parking_record_new` | 是否存在 `car_plate LIKE '%xxx%'` 片段模糊 | 大表片段模糊至少 `P1` | 完整车牌 `car_plate = ?`；前缀 `LIKE '鲁MA8%'`；片段需限制范围或搜索系统 |
| `parking_lot_statistics` | 是否存在 `DATE_FORMAT(statistics_time, ...)` 等函数包裹索引列 | 核心报表全表扫描 `P1`，严重 `P0` | 改范围：`statistics_time >= ? AND statistics_time < ?` |
