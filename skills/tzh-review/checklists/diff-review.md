# 变更总体审查清单

## 目标

基于 baseline 与 HEAD 的差异，建立完整变更地图，防止漏扫文件、漏扫项目、漏扫数据库对象。

## 检查项

| 检查项 | 关注点 |
|---|---|
| baseline 是否确定 | 默认 `master`；只有用户显式指定时才覆盖 |
| diff 范围是否明确 | `baseline...HEAD` 与提交区间一致 |
| 是否存在未提交改动 | `git status` 是否含未暂存或未提交内容 |
| 是否存在多仓库/多模块 | 是否需要切换到多项目模式 |
| 是否识别到配置变更 | `application.yml`、`bootstrap.yml`、Nacos key |
| 是否识别到数据库变更 | SQL、DDL、DML、修复脚本、索引 |
| 是否识别到消息/任务变更 | MQ、XXL-Job、定时任务 |
| 是否识别到测试变更 | 单测、集成测试、压测脚本 |
| 是否识别到发布单元变更 | Dockerfile、Jenkinsfile、k8s、Helm |

## 输出要求

- 变更文件清单
- 变更类型分类
- 变更涉及项目/服务列表
- 变更涉及业务域列表
- 变更涉及数据库对象清单
- 变更涉及配置与发布清单

## 风险提醒

- diff 触达多个服务目录而仍按单项目评审，至少 `P1`
- 漏掉脚本、配置、SQL、测试文件，至少 `P1`
- baseline 误用导致 diff 范围失真，至少 `P1`
