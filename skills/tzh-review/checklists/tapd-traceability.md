# TAPD 追踪清单

## 强规则

- TAPD 编号必填。
- 未提供 TAPD 时必须先询问并暂停。
- 不允许仅凭分支名或 commit message 猜测 TAPD 并继续。
- 支持多 TAPD。
- 支持一个 TAPD 对多个项目。
- 支持多个 TAPD 对一个项目。

## 检查项

| 检查项 | 说明 |
|---|---|
| TAPD 是否齐全 | 用户是否明确提供全部 TAPD |
| 每个 TAPD 是否有变更目标 | 至少一句话说明变更目的 |
| 是否建立 TAPD 正向矩阵 | TAPD -> 项目/服务/文件/变更 |
| 是否建立反向矩阵 | 文件/变更 -> TAPD |
| 是否存在未映射变更 | 未映射项必须标记 Unknown |
| Unknown 是否落核心域 | 若是，至少 `P1` |
| TAPD 与测试范围是否对应 | 每个 TAPD 应有必测场景 |

## 输出模板

### 正向矩阵

| TAPD 编号 | 变更内容 | 项目/服务 | 文件/模块 | 风险域 | 证据 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

### 反向矩阵

| 文件/模块/脚本 | 变更类型 | 所属项目/服务 | 关联 TAPD | 未关联原因 | 风险等级 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

## 风险提醒

- 核心业务代码无法映射 TAPD：至少 `P1`
- 核心数据库 / SQL / 支付 / 对账 / 开闸变更无法映射 TAPD：优先按 `P1` 处理，若影响资金或核心可用性，直接 `P0`
