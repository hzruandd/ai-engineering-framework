# Java / Spring 审查清单

## 适用范围

Spring Boot、Spring Cloud Alibaba、Dubbo、MyBatis Plus、Redis、MySQL 等后端代码变更。

## 检查项

| 检查项 | 关注点 |
|---|---|
| 分层职责 | Controller / DubboApi 是否只做参数校验、日志、转调 |
| 业务逻辑位置 | 是否误放到接口层、Controller、DubboApi |
| 事务边界 | 增删改、批量、多表是否有事务 |
| 幂等性 | 支付回调、券核销、开票、补单、开闸是否具备幂等 |
| 异常处理 | 是否吞异常、是否错误捕获业务异常 |
| 日志 | 是否有关键链路日志、traceId、敏感信息脱敏 |
| Dubbo | 超时、重试、线程池、泛化调用、服务版本兼容是否合理 |
| Nacos / 配置中心 | 是否引入高风险配置变化、明文敏感配置、灰度开关漂移 |
| 缓存 | Redis / Tair 是否符合先更库再删缓存原则、缓存键是否带隔离维度 |
| 消息与任务 | EMQX / MQTT、MQ、XXL-Job 补偿链路是否可追踪、可幂等 |
| 并发控制 | 是否误用分布式锁、乐观锁、唯一约束 |
| API 契约 | 入参、返回值、兼容性、字段语义是否清楚 |
| 可维护性 | 命名、重复代码、复杂度、策略拆分是否合理 |

## 重点高风险

- 支付、订单、发票、清分、对账、开闸链路缺少幂等：`P0`
- 多租户、停车场、商户隔离缺失：`P0`
- 核心事务缺失导致部分成功：`P1` 至 `P0`
- Dubbo 超时、重试、线程池配置导致核心链路雪崩：至少 `P1`
- Nacos 明文敏感配置、错误灰度开关、错误命名空间切换：至少 `P1`
- 日志、traceId 缺失导致无法追责：至少 `P1`
