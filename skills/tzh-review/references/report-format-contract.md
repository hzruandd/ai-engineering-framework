# 正式评审报告格式约束

## 目标

确保 `tzh-review` 在多次生成报告时保持稳定版式，尽量贴近现行《智慧停车生态_代码评审报告_v1.3.pdf》与既有历史报告的输出风格，而不是每次重新组织章节。

## 固定外观骨架

报告必须按以下骨架输出：

1. 顶部主标题：`# 智慧停车生态 · 代码评审报告`
2. 封面信息表：两列表格，表头固定为 `| 项目 | 内容 |`
3. 分隔线：封面表后使用 `---`
4. 目录：固定为 `## 目录`
5. 正文：一级标题使用 `## 1. ...` 到 `## 16. ...`
6. 每个一级章节之间使用 `---`
7. 附录：放在正文之后
8. 报告结尾保留“AI 辅助生成”说明

## 默认文件名约束

- 正式评审报告默认文件名固定为：`智慧停车生态_代码评审报告_v1.4_<日期>.md`
- `<日期>` 固定使用 `YYYY-MM-DD`
- 不得在默认文件名中追加 `TAPD`、`by_codex`、`by_cc`、分支名、仓库名、评审人等随机后缀
- 若用户未明确指定其他文件名，则必须使用该默认命名方式

## 封面信息表固定顺序

## 正文固定章节

目录与正文一级标题保持一致：

1. 评审概述
2. TAPD 变更追踪矩阵
3. 多项目联合评审范围
4. 文件变更清单
5. 系统背景与关键链路
6. 设计与实现评审
7. 代码质量审查
8. 逻辑正确性与业务一致性验证
9. 数据库与 SQL 专项评审
10. 性能影响评估
11. 安全性审查
12. 日志与可观测性
13. 测试建议与验证计划
14. 风险矩阵与评审决议
15. 亮点总结
16. 待改进项

附录固定为：
- 附录 A：证据表
- 附录 B：评分细则
- 附录 C：Unknowns 与人工确认项
- 附录 D：代码变更与 TAPD 反向追踪表

## 表格风格

- 评估性内容优先使用表格，不要频繁在同一章节内切换多种版式。
- 表头命名固定后尽量不改。
- 封面表使用 `**字段名**` 强调。
- 风险、测试、索引、SQL、行动项等内容必须落在固定表格中。

## 结论区约束

- 封面信息表中的 `评审结论` 与正文 `14. 风险矩阵与评审决议` 保持一致。
- 不得预填“通过”。
- 缺少关键证据时可写 `待决议`、`Unknown` 或 `待补证据`，不得虚构通过。

## 评分区约束

- 若需要评分，统一放入附录 B。
- 封面表中的 `综合评分` 只引用附录 B 的最终结果。
- 没有足够评分依据时，可写 `待评估`。
- 附录 B 必须显式包含 `权重`、`维度得分`、`加权得分` 三列，不得退回隐式权重写法。
- 固定公式为：`综合评分 = Σ(维度得分 × 权重)`。
- 不允许出现“主观权重调整”“人工二次调权”等表述。
- 风险结论优先于分数；`P0`、未闭环 `P1`、核心域 `Unknown` 未确认时，分数不得覆盖裁决。
- 附录 B 应固定包含 `B.1 扣分口径` 与 `B.2 维度扣分参考` 两个子节，避免同类风险在不同报告中出现漂移评分。

## 可变项与不可变项

可变项：
- 具体表格行数
- 子章节文字说明
- 是否增加场景化说明或流程图
- 针对本次评审增加的证据编号

不可变项：
- 主标题
- 默认文件名规则
- 封面表结构
- 目录结构
- 一级标题顺序和命名
- 结论区位置
- 附录顺序

## 生成规则

- 先复制模板骨架，再填内容。
- 不要先自由写报告，再回头套模板。
- 如遇新场景，优先扩充章节内子标题，不要新开同级一级章节。
